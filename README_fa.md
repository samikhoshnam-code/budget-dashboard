# راه‌اندازی و کار روزانه داشبورد

## یک‌بار راه‌اندازی
1. نصب: Python 3 و Git. سپس در CMD بزنید: `pip install openpyxl cryptography`
2. در GitHub یک مخزن بسازید و این پوشه را در آن بگذارید (git init، add، commit، push).
3. در مخزن: Settings ← Pages ← Source = `main` و پوشه `/docs`. آدرس سایت همان‌جا نمایش داده می‌شود.
4. یک **رمز قوی** (حداقل ۱۰ نویسه، بهتر ۱۵+) انتخاب کنید و فقط به مدیران بدهید.

## کار روزانه (بعد از پایان کار، ۲ دقیقه)
1. فایل اکسل عملکرد (همان قالب `Budget_Report_Mehr1405.xlsx`) را در پوشه `input` بگذارید. ردیف‌های جدید بانک را زیر شیت `ریز تراکنش ...` بچسبانید؛ ستون «دسته بندی» را خالی بگذارید تا قواعد خودکار پرکنند (اگر پر کنید، همان رعایت می‌شود).
2. روی `update.bat` دوبار کلیک کنید و رمز سایت را وارد کنید.
3. چند دقیقه بعد سایت به‌روز است. اقلام نیازمند بررسی در `review.csv` می‌آید؛ دسته‌شان را در اکسل بنویسید تا دفعه بعد قطعی شوند.

## ماه جدید
- در شیت `Fact_Budget` ردیف‌های بودجه ماه جدید را اضافه کنید (MonthKey مثل `1405/08`). ریز تراکنش آن ماه را در یک شیت جدید با نام `ریز تراکنش آبان` (یا هر نامی که با «ریز تراکنش» شروع شود) بگذارید. سایت ماه‌ها را خودکار می‌شناسد.

## امنیت
- فقط `docs/data.enc` (رمزگذاری‌شده با AES-256) منتشر می‌شود؛ اکسل و `review.csv` هیچ‌وقت در Git نمی‌روند (در `.gitignore` است).
- امنیت به قدرت رمز بستگی دارد. اگر رمز لو رفت، رمز را عوض و `update.bat` را اجرا کنید؛ ولی نسخه‌های قدیمی فایل در تاریخچه Git با رمز قدیمی باز می‌شوند.
- مخزن رایگان GitHub Pages عمومی است. کسی که آدرس را بداند صفحه ورود را می‌بیند ولی بدون رمز داده‌ای نمی‌بیند.

## تغییر قواعد دسته‌بندی
فایل `tools/rules.py`: ترتیب قواعد مهم است. دسته‌های ثابت هم همان‌جا تعریف شده‌اند.

## فروش و تولید
تب‌های فروش و تولید فعلاً نمونه‌اند. برای وصل‌کردن، فایل ماهانه فروش و تولید را با ستون‌های ماه، محصول، برنامه و عملکرد بدهید تا همین اسکریپت آن‌ها را هم بخواند.
